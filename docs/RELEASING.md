# Выпуск обновления

Канал релизов: `everth1337/1337-player`. Публичные релизы — стабильные версии `vX.Y.Z`, пока только Android ARM64. Версия 2.4.6 использует `versionCode=506`; каждый следующий код должен увеличиваться.

## Обычный выпуск

1. Обнови `appVersionName` и увеличь `appVersionCode` в `base/gradle.properties`.
2. Добавь раздел `## X.Y.Z` в `CHANGELOG.md`, опиши пользовательские изменения и проверки.
3. Выполни проверки, закоммить изменения, отправь их в `main`.
4. Создай тег на этом коммите и отправь его:

```sh
git tag v2.4.7
git push origin main
git push origin v2.4.7
```

Workflow **Publish release** проверяет совпадение версии и тега, запускает регрессионные тесты, собирает подписанный APK и публикует релиз с соответствующим исходным кодом, `SHA256SUMS` и `release.json`. До успешной загрузки файлов релиз остаётся черновиком. Уже опубликованные версии не заменяй: исправление выпускай новым тегом и кодом.

Для повторного запуска на существующем теге можно использовать Actions → Publish release → Run workflow. Если предыдущая попытка уже создала черновик, сначала проверь его; команда создания релиза намеренно не перезаписывает существующий релиз.

## Секреты подписи

В Settings → Secrets and variables → Actions нужны:

| Имя | Значение |
| --- | --- |
| `PLAYER_KEYSTORE_BASE64` | Base64 файла ключа релизной подписи |
| `PLAYER_KEYSTORE_PASSWORD` | Пароль хранилища |
| `PLAYER_KEY_ALIAS` | Алиас ключа |
| `PLAYER_KEY_PASSWORD` | Пароль ключа |

Они не входят в Git, исходные архивы и APK. Не вставляй их в issue, лог или workflow. Сохраняй резервную копию ключа отдельно: без прежнего ключа обновить установленные приложения нельзя. PR-workflow не использует секреты релиза. Записывать код и теги в основной репозиторий должны только доверенные сопровождающие.

## Локальный выпуск при недоступности Actions

Собери релиз тем же ключом на чистом коммите с нужной версией. Затем:

```sh
python tools/release_player.py --check-tag v2.4.7 --package
```

Папка `build/player-release/` содержит APK, архив ровно текущего коммита, контрольные суммы, манифест и заметки. Перед публикацией проверь подпись через `apksigner verify --print-certs`. Файлы выкладывай в GitHub Release с соответствующим тегом, а не в дерево Git.

## Как обновляется приложение

2.4.6+ читает GitHub Releases этого проекта, сравнивает версии и выбирает APK своей архитектуры/канала. Пользователь подтверждает установку средствами Android. Проверка обновлений не отправляет Spotify-токены GitHub. Сборки 2.4.5 и старше требуют ручного первого обновления.
